## Global Constraints

- Lens names: **focus** (Jobs), **data** (Ng), **craft** (Ive). Real names appear only in the parentheses; no text quotes or claims endorsement from a real person.
- Design panel: craft, `impeccable`, `ui-ux-pro-max`. Product panel: focus, craft, data.

# Lens

A lens is advice. The user's approval stays the gate: a lens never approves a design, never blocks one, and never starts implementation.

## Which panel

| Situation | Panel |
| --- | --- |
| A design that needs review (UI, UX, layout, visual style, components, on-screen copy) | design panel |
| A new feature or product idea in brainstorm | product panel |
| Both at once | design+product, one page |
| The user says "3 lens", or `/lens product` | product panel |
| `/lens design` | design panel |
| `/lens` with no argument | pick from the rows above |

Not for bug fixes, internal tooling or refactors, unless the user asks.

## Run the lenses

1. **Subject.** Name what is under review: the in-chat design, the spec, a mockup or screenshot, a running page, or the product idea with its intent note.
2. **Lenses.** Run each lens of the panel in this order; each returns a verdict (`pass` or `change`), its findings, and the change made for each finding. The question each lens asks is in `${CLAUDE_PLUGIN_ROOT}/skills/lens/reference.md` § Lenses.
   - Design panel: craft, then `impeccable` (its critique pass on the subject), then `ui-ux-pro-max` (style, palette, font pairing, UX guidelines, stack patterns).
   - Product panel: focus, then craft, then data.
   - When `impeccable` or `ui-ux-pro-max` is not installed or not callable here, mark that lens `skipped (not available)` and go on; craft always runs, since it needs no skill.
3. **Apply.** In brainstorm, apply each change to the design before you present it, so the user approves the changed design. Inside `/orchestrate`, the `change` findings go to review next to the reviewers' findings.
4. **Page.** Write the lens page as `${CLAUDE_PLUGIN_ROOT}/skills/lens/reference.md` § Page describes. `<topic>` is the spec's topic slug (or a short slug of the design's name).
5. **Save or publish** (below).
6. **Block.** Write the `## Lens` block into the in-chat design or the spec, exactly as `${CLAUDE_PLUGIN_ROOT}/skills/lens/reference.md` § Lens block shows.
7. **Tell the user** the page link or path, the verdict, and one line per lens that changed something.

# Lens reference

## Lenses

Our own interpretation of each person's known principles, not quotes.

| Lens | Panel | Question |
| --- | --- | --- |
| Focus (Jobs) | product | What is the one thing this must do or say? Cut whatever does not change what the user does next. Judge the whole experience end to end. |
| Craft (Ive) | both | Reduction and care. Remove until only the essential remains; calm by default, emphasis only for attention; precise type, spacing and motion. |
| Data (Ng) | product | Data first and actionable. What will we measure, does every metric point to a next action, and does any AI part have an eval and a way to find its errors? |
| `impeccable` | design | Its critique pass: hierarchy, cognitive load, accessibility, states, anti-patterns. |
| `ui-ux-pro-max` | design | Style, palette, font pairing, UX guidelines and stack patterns, checked against its data. |

## Page

In this order:

1. Title (the design topic) and the overall verdict (`pass` when every lens passed, else `change`).
2. The design or mockup itself, when there is one: screenshot, comp or embedded markup.
3. One table per lens that ran: `Finding | Change made | Lens`. A skipped lens shows one row: `skipped (not available)`.
4. "Not done yet": suggestions not applied, each with the lens that made it.

Self-contained HTML that reads well at phone width and in dark mode.

## Lens block

The block goes into the in-chat design or the spec, verbatim in this shape:

```
## Lens
- Panel: design+product
- Focus (Jobs): The board must say which session needs you; everything else is secondary.
  - Drop the per-agent token column from the first screen; it never changes what you do next.
  - Merge the two status chips into one.
- Data (Ng): Every number on the card points to an action.
  - Show escalation rate per stage, with the worst stage first.
- Craft (Ive): Calm by default; only the waiting card glows.
- Verdict: change — artifact: https://claude.ai/artifact/EXAMPLE
```

- `Panel:` is `design`, `product` or `design+product`.
- Each lens line has a one-sentence headline, then any number of insights: no limit on count or length. A lens with nothing more stays one line.
- A design-only run writes `- Focus (Jobs): n/a` and `- Data (Ng): n/a` with no insights; the `impeccable` and `ui-ux-pro-max` findings stay on the page, not in the block.
- A product or design+product run fills all three lenses.
- No line quotes a real person.

```python
#!/usr/bin/env python3
"""Is the lens release no worse than the previous release on design tasks? Spec 2026-10-28-lens-design.md §8.

  python3 tools/compare_lens.py --old DIR [--runs N] [--claude PATH]   exit 0 PASS, 1 FAIL, 2 setup error

Runs each prompt in tools/fixtures/lens/ headless (`claude -p ... --output-format json --plugin-dir <side>/claude`)
on the old release checkout (DIR) and on this checkout, sides alternating per run, in a fresh temp folder each time.
PASS when, per prompt, the median added time is at most 90 s, the median added tokens at most 25k, and the new side
never has more permission prompts (denials in -p mode) than the old. Run it from a session where the account's own
Dryas plugin is not also loaded, or both copies run; the release step says how.
"""
import argparse
import json
import statistics
import subprocess
import sys
import tempfile
from pathlib import Path
from typing import Dict, List, Tuple

REPO = Path(__file__).resolve().parents[1]
FIXTURES = REPO / "tools/fixtures/lens"
TOKEN_KEYS = ("input_tokens", "output_tokens", "cache_creation_input_tokens", "cache_read_input_tokens")


def parse_result(stdout: str) -> Dict[str, int]:
    try:
        d = json.loads(stdout)
    except ValueError as e:
        raise ValueError("not a claude -p json result: %s" % e)
    if not isinstance(d, dict) or "duration_ms" not in d:
        raise ValueError("not a claude -p json result")
    usage = d.get("usage") or {}
    return {"ms": int(d["duration_ms"]), "tokens": sum(int(usage.get(k) or 0) for k in TOKEN_KEYS),
            "prompts": len(d.get("permission_denials") or [])}


def verdict(old: List[Dict[str, int]], new: List[Dict[str, int]], max_ms: int = 90000,
            max_tokens: int = 25000) -> Tuple[bool, List[str]]:
    med = lambda runs, k: statistics.median(r[k] for r in runs)
    dms, dtok = med(new, "ms") - med(old, "ms"), med(new, "tokens") - med(old, "tokens")
    lines, ok = [], True
    if dms > max_ms:
        ok = False
        lines.append("FAIL time: +%d ms median (limit %d)" % (dms, max_ms))
    if dtok > max_tokens:
        ok = False
        lines.append("FAIL tokens: +%d median (limit %d)" % (dtok, max_tokens))
    if max(r["prompts"] for r in new) > max(r["prompts"] for r in old):
        ok = False
        lines.append("FAIL prompts: new side asked more often than the old one")
    lines.append("time +%d ms, tokens +%d" % (dms, dtok))
    return ok, lines


def build_cmd(claude: str, side: Path, prompt: str) -> List[str]:
    return [claude, "-p", prompt, "--output-format", "json", "--plugin-dir", str(side / "claude")]


def run_once(claude: str, side: Path, prompt: str) -> Dict[str, int]:
    with tempfile.TemporaryDirectory() as cwd:
        p = subprocess.run(build_cmd(claude, side, prompt), cwd=cwd, capture_output=True, text=True, timeout=900)
    return parse_result(p.stdout)


def main(argv=None) -> int:
    ap = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    ap.add_argument("--old", required=True, type=Path, help="checkout of the previous release (e.g. v2.5.0)")
    ap.add_argument("--runs", type=int, default=3)
    ap.add_argument("--claude", default="claude")
    a = ap.parse_args(argv)
    if not (a.old / "claude").is_dir():
        print("no claude/ in %s" % a.old, file=sys.stderr)
        return 2
    ok = True
    for f in sorted(FIXTURES.glob("*.md")):
        prompt = f.read_text(encoding="utf-8").strip()
        old, new = [], []
        for i in range(a.runs):
            for side, out in ((a.old, old), (REPO, new)) if i % 2 == 0 else ((REPO, new), (a.old, old)):
                out.append(run_once(a.claude, side, prompt))
        good, lines = verdict(old, new)
        ok = ok and good
        print("%s: %s" % (f.stem, "PASS" if good else "FAIL"))
        for l in lines:
            print("  " + l)
    return 0 if ok else 1


if __name__ == "__main__":
    sys.exit(main())
```
